# AGENTS.md - Freax (OpenComputers Lua OS)

Freax is a from-scratch OpenOS replacement for OpenComputers (Minecraft
1.7.10, GTNH). Lua 5.2-ish (OC Lua). Repo root mirrors the installed root
(`/`); status and feature list live in `README.md`.

## Verification model (read first)

- The host has `luajit` but **no OC runtime**. Use it only for syntax:
  `luajit -e 'assert(loadfile("boot/kernel/main.lua"))'` per changed file.
- **Do not attempt behavioral testing on the host.** The user runs every
  test in-game and reports back. Never infer that a change works from a
  host run. There is no CI, test suite, linter, or typechecker.

## Layout

- `boot/kernel/main.lua` - kernel (~87K of Lua; the single biggest RAM cost);
  `init.lua` - boot entry (mounts VFS, compiles kernel, hands off)
- `lib/*.lua`, `bin/*.lua`, `sbin/*.lua` install to the same paths
- `manifest` -> `/manifest` (ship list). `VERSION` -> `/VERSION` is the only
  version source: `bin/sh.lua` reads it for the banner; `etc/motd` must not
  hardcode a version.
- `usr/man/*` are extensionless man pages, not code
- `etc/` -> `/etc/`: `motd`, `hostname` (local-only), `profile.lua` (sourced
  by the shell: aliases + env), `apt/sources.list`, `systemd/*.unit`
- `selfcheck.lua`, `mksums.lua` and `.gitignore` are dev-only (in
  `manifest` for demo protection, but not installed)
- `SHA256SUMS` (repo root) is the per-file checksum index for efficient OS
  updates; regenerate with `luajit mksums.lua`. It is shipped/installed too:
  the installed copy records synced hashes so `sysupdate`/`sysupgrade`
  compare tables instead of re-hashing every file.

## Adding a file? Update `manifest`

`manifest` is the single ship list. It drives `bin/install.lua` (parses
`/manifest` at runtime), `apt sysupgrade` (`lib/sysupdate.lua`), and
demo-mode protection. Never-installed entries live in `SKIP_INSTALL`
(install) / `SKIP_DEV` (sysupdate): `.gitignore`, `README.md`,
`selfcheck.lua`, `/etc/hostname`. The account DB (`/etc/passwd`,
`/etc/shadow`) is generated by the installer, never listed.

## Shared module runtime (kernel)

- Libraries compile **once** into a machine-wide `sharedEnv`, cache in
  `sharedLibs`, and dispatch to the running process via `currentP`.
- `SHARED` allowlist = core boot libs (`fs term text transforms package
  filesystem`). Everything else loads per-process and frees on exit.
  Adding a lib to `SHARED` permanently raises the machine floor - avoid.
  `shell` and `sh` are deliberately per-process: they hold aliases, builtins
  and `$?` that belong to one shell, not to the machine.
- In processes, `freax`/`io`/`os` are dispatch proxies that resolve to
  `currentP.rawFreax`/`rawIO`/`rawOS`. Module code must not capture
  process-specific values at load time (only call them at runtime).
- `lib/computer.lua`, `lib/unicode.lua`, `lib/bit32.lua` are shims that
  re-export kernel-injected process globals so `require()` resolves them.

## Kernel / process rules

- Processes are coroutines with a private `_ENV`. Yield points only:
  `freax.wait`, `freax.pullEvent`/`pollEvent`, `ttyReadLine`, `freax.exit`,
  sleeps.
- The scheduler resumes every process every tick (0.05s), not only on signal
  arrival, so daemons progress on an idle machine.
- No ambient hardware authority: hardware only through `freax.*` syscalls.
  `component` is an OpenOS-compat bridge over `freax.*` (`lib/component.lua`),
  and `computer` is an info-only subset.
- OC filesystem proxies use dot-calls: `fs.open(path)`, never `fs:open()`.
- Ctrl+C: the kernel tracks the modifier and kills the **foreground tree**
  (pids spawned with a `stdio` table: commands via `spawnIO`/`os.execute`/
  `io.popen`). At a bare prompt `ttyReadLine` returns nil and the shell
  treats it as an empty line. `bin/sh.lua` pcalls `runLine` so a command
  error can never kill the shell (that would look like a relogin).
- `/dev` (devfs) mounts lazily on first `/dev` access, not at boot.
- Symlinks are a kernel RAM table, lost on reboot; cycles must error, not hang.
  Packages must therefore not install symlink entries (`dpkg` rejects them).
- Removable-media autorun is disabled on purpose: kernel-phase `load` would
  run media code with kernel authority, outside process credentials.
- `K.start` -> `/sbin/systemd.lua`, else `/bin/login.lua`, else `/bin/sh.lua`.
- `/sbin/systemd.lua` is PID 1 and refuses to start a second instance
  (manual `systemd` otherwise spawns another login).

## Credentials (kernel-owned identity)

- Every process carries `uid/euid/gid/egid` plus `home`, set in `K.spawn` and
  inherited by `myInh()`. `freax.getuid/geteuid/getgid/getegid` expose them;
  `USER`/`LOGNAME` are display-only and must never authorize anything.
- Root-only: mount/umount, label writes, EEPROM writes, boot address, redstone,
  screen resolution change, reboot/shutdown, `freax.spawnAs`. `kill`/`wait`
  require root or same UID (root may wait on any child; a user may only wait on
  its own children).
- Non-root writes are limited to `$home` and `/tmp/u<uid>`; `/etc/shadow` is
  unreadable to non-root. This is a path policy, not POSIX mode bits: no
  per-file ownership exists yet, so any account may write inside another
  account's home. Persistent mode metadata is the planned fix.
- `su` and `passwd` are the only trusted setuid entry points: `K.spawn` raises
  `euid` to 0 for `/bin/su.lua` and `/bin/passwd.lua`. Keep that list tiny.
- `login`/`su` create sessions with `freax.spawnAs(uid, gid, home)`.

## Low-RAM discipline (real hardware OOMs)

- Kernel + boot libs dominate the floor (~384K tier on minimal hardware).
- Never build a whole file with `data = data .. chunk` (O(n^2) peak). Read
  into a `parts` table then one `table.concat`; see `init.lua` and the
  kernel's `vfsLoad`. Minifying/stripping does **not** reduce retained Lua.
- **OC's sandbox `load` does not support reader functions** - `load(reader)`
  yields a nil chunk. Always `load(string, name, "t", env)`.
- Install verification uses `fs.size`, not full reads, for the same reason.

## Shell / libs conventions

- Parsing/execution lives in `lib/sh.lua`; `bin/sh.lua` is the REPL + builtins.
- `os.execute` always returns `true` (it does not propagate the child's exit
  code), so don't use it for pass/fail checks.
- `lib/internet.lua` wraps the kernel's fd-based net API
  (`freax.netRequest`/`netConnect` + `fsRead`/`fsWrite`/`fsClose`) in the
  OpenOS callable-stream shape. The kernel returns fds, not handle objects.
- `term.gpu()` is a tty-backed shim (OpenOS compat); `term`/`tty` are thin
  wrappers over kernel tty syscalls.

## Update flow

- **Packages** (`apt update` + `apt install/upgrade/...`): Debian-style
  repositories (`deb` lines in `/etc/apt/sources.list`, plus
  `/etc/apt/sources.list.d/*.list`), indexes under `/var/lib/apt/lists`,
  archives under `/var/cache/apt/archives`, installed DB under
  `/var/lib/dpkg`. `lib/apt.lua` owns sources/index/resolution and drives
  `lib/dpkg.lua`, which owns unpack/configure/remove, conffiles and
  maintainer scripts. `lib/fpkg.lua` is the uncompressed `.fpkg` container
  and RFC822/version/dependency primitives. Tools: `bin/dpkg.lua`,
  `bin/dpkg-deb.lua` (build), `bin/apt-ftparchive.lua` (index).
- **OS self-update** (`apt sysupdate` / `apt sysupgrade`): the legacy
  manifest updater, kept behavior-identical in `lib/sysupdate.lua`.
  `sysupgrade` uses the remote version cached by `sysupdate`, so the order
  is: push -> `apt sysupdate` (verify the `Remote:` line) ->
  `apt sysupgrade`.
- **Efficient updates**: `SHA256SUMS` (generated by `mksums.lua`) lets
  `sysupdate` report changed files and `sysupgrade` download only files
  whose content differs, verifying each against its checksum. 0-byte files
  (`.gitkeep`) are valid. A stale `SHA256SUMS` is detected via the
  `/VERSION` hash and falls back to a full download, so always regenerate
  and commit it after editing shipped files.
- Network fetches append a cache-buster to bypass GitHub raw's CDN; without
  it a just-pushed `VERSION`/`manifest`/index still serves stale.
- `PRESERVE` (`/etc/passwd|shadow|hostname`) and `NEEDS_REBOOT` (`init.lua`,
  kernel) are enforced in `lib/sysupdate.lua`.
- `apt sysupdate` ignores `deb` lines and uses the first bare URL in
  `/etc/apt/sources.list`, falling back to the built-in GitHub URL. Keep the
  shipped sources.list to `deb` lines only.
- Package tooling must stay out of the kernel `SHARED` allowlist (it loads
  per-process); use streaming sha256 (`sha256.new():update():hex()`) and 4K
  chunked IO, never whole-archive reads.

## Verify in-game (the user's job)

- `lua /selfcheck.lua` - dev smoke test (requires, thread join/order,
  symlink-cycle errors, `os.execute` spot checks). Writes its fail file to
  `/tmp` (root is read-only on uninstalled media).
- `install` needs a second writable HDD; tmpfs targets are skipped by design
  (`--to=ADDR` forces, `--from=ADDR` pins source).

## Before committing

- Syntax-check every touched `.lua` with `luajit`.
- After changing any shipped file, run `luajit mksums.lua` and commit the
  updated `SHA256SUMS` with the change.
- `git status`; never commit dev leftovers (`s_*.txt`, `*.bak`,
  `dmesg_dump.txt`, `iotest.txt` - already in `.gitignore`).
- Do not commit unless the user explicitly asks.
